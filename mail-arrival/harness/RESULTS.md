# Local importer and arrival evidence

The final synthetic run used the isolated local FreeScout stack, an IMAP fixture bound to container loopback and three foreground headless desktop browsers. It did not contact Gmail or establish production or physical-phone performance.

- Named-folder integration: `results/arrival-folders-20261113k-folders.json`, 14 checks passed. This exercised Crockd's INBOX and pilot folder, and the default Fiveways All Mail, Spam and Bin names, including cross-folder identity replay and status policy. The provider is synthetic.
- Full importer integration: `results/arrival-release-20261113j-integration.json`, 46 checks passed. This includes read-before-fetch and unchanged source flags, new messages and replies, exact attachment bytes, replay, provider error and checkpoint recovery, UIDVALIDITY reset, a pre-commit fault after a native write with rollback and exact-once retry, paused target recovery, overlapping worker lock and simultaneous cross-mailbox delivery.
- Timing: `results/arrival-release-20261113j-timing.json`. All 60 messages, 20 per mailbox, were committed and matched to visible inbox rows. There were no failed polls or unresolved side effects. The backend recorded 29 internally recovered transaction conflicts. Conservative per-mailbox p95 upper bounds for provider publication to visible row were 6.952s, 10.701s and 9.730s; commit to visible row were 1.431s, 1.288s and 1.426s. Both local targets, under 30s and under 2s respectively, were met. Receipt time is bounded by synthetic provider file publication, commit by pre/post transaction callbacks and clock offset by host/container samples. Visibility means an in-viewport row after two animation frames. This does not measure real Gmail receipt or delivery.
- Release-only baseline reconciliation: 36 fake-store and 13 temporary-PDO checks passed locally. See `tests/backend/results/baseline-reconcile-receipt.json` for source hashes. This does not establish a production outcome.
- Raw synthetic provider state, operation transcript and server log are retained under each run ID. The fixture providers were stopped after export.

Earlier results remain material. The first timing attempt `arrival-final-20261112b` ended after nine arrivals on an uncaptured mailbox-2 poll error. The subsequent 60-message run `arrival-release-20261112c` completed all observations but failed the local budgets, with ten native poll failures. Its database exception was diagnosed as driver 1020, and the fixed backend passed the final rerun above. The shorter diagnostic runs and their failure details remain in `results/`. A transiently recovered transaction conflict is still a real operating signal; do not present the final local pass as proof that production will behave identically.
