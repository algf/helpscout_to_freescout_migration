# Synthetic provider harness

This server is a deliberately limited IMAP fixture, not Gmail. It binds only to `127.0.0.1` and must run inside the guarded, network-isolated FreeScout container. It accepts only the synthetic accounts generated by `fixtures/make_state.py`, with the fixed synthetic password in the test code. Never use mailbox credentials or real messages. Unsupported commands fail with `BAD`; a successful fixture test does not prove production provider compatibility.

The state contains synthetic SMTP-formatted MIME, per-folder UIDVALIDITY/UIDNEXT, INTERNALDATE, flags and stable numeric Gmail-style message and thread IDs. IDs derive from a unique run identity. Reply messages share the original thread ID. A read message tests eligibility without an unread-only search. The attachment fixture has deterministic local bytes. Source Date is deliberately older or later than receipt in two fixtures; it must never be used as a delivery-time measurement.

`harness/inject.py` atomically publishes one synthetic message and returns timestamps bracketing the state-file rename. They are a bound on fixture-provider availability, not Gmail receipt. The event log contains the run, synthetic account, folder, operation and timestamp, not body or address. Measure FreeScout commit and actual visible browser state independently. Host scheduling, PHP emulation and synthetic network behaviour limit the meaning of these local timings.

Run `python3 -m unittest discover -s mail-arrival/tests/integration -v` for the standalone protocol test. After the isolated stack is guarded and approved, `node mail-arrival/scripts/harness-provider.mjs start <unique-run>` starts the fixture; `harness-webklex.mjs <unique-run>` tests the installed Webklex protocol client without importing. `harness-provider.mjs stop <unique-run>` checks the process identity before stopping it. These checks alone do not establish importer correctness, browser visibility, or any arrival latency target.
